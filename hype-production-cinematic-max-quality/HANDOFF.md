## Что уже работает (сделано в предыдущем чате)

### Десктоп: 3D-коридор (cinematic)

Полностью переписан с «AAA sci-fi нагромождения» на **минимальный премиум-коридор в стиле Apple Vision Pro**:
- глянцевые чёрные стены (metalness 0.92)
- одна световая щель в потолке
- утопленные световые планки на стенах и линии на полу
- плотный туман для глубины
- маяк-«выход» в конце коридора
- 17 сцен — это одна и та же геометрия, меняется только **цвет акцентов** (карта `SCENE_ACCENTS` в коде)
- камера — плавный fly-through без зумов и резких движений

### Мобильная версия (cinematic mobile)

При viewport ≤720px на `<html>` ставится класс `is-mobile-view` и показывается **отдельный полноэкранный mobile layout**:
- 12 сцен-карточек на весь экран со snap-scroll
- меню-drawer (Проекты / Процесс / Фон / О нас / Контакты)
- bottom-sheet с формой («Обсудить проект»)
- вертикальные dot-индикаторы прогресса слева
- нижний счётчик `XX / 11` и золотая полоса прогресса
- кнопка-гамбургер сверху
- лого HYPE PRODUCTION сверху

Тяжёлый Three.js на мобиле не запускается — лёгкая версия. Десктопный 3D-коридор не трогается.

### Chooser-экран

При заходе **без `?mode=` параметра** показывается полноэкранный chooser с тремя тайлами: **LANDING / MULTIPAGE / CINEMATIC**. У каждого мини-превью своего формата. Клик → редирект с `?mode=X` → попадаешь внутрь выбранного варианта.

Мобильные **пропускают chooser** и сразу попадают в cinematic-мобильную версию.

Chooser-экран показывается **на каждом визите** (никаких localStorage — это было сознательное решение).

В правом нижнем углу всех режимов есть кнопка **«← сменить формат»**, возвращает на chooser.

### Три режима

CSS-класс на `<html>` определяет режим: `mode-landing`, `mode-multipage`, `mode-cinematic`.

**LANDING** — конверсионный одностраничник:
- минимальный sticky хедер (лого + одна кнопка START PROJECT)
- спрятаны: счётчик сцен, языковой переключатель
- **прилипшая снизу CTA-полоска** «Готовы запускать? · ОБСУДИТЬ ПРОЕКТ»
- тесный поток секций (60px падинг вместо 100vh)
- без 3D, без vignette, без portal-flash

**MULTIPAGE** — сайт-с-разделами с навигацией:
- **видимая горизонтальная навигация** под шапкой: Главная · Услуги · Работы · Цены · Процесс · Контакты
- активный раздел подсвечивается синим и подчёркивается на скролле (IntersectionObserver)
- у каждой секции справа сверху **номер страницы** (`02`, `03`) с акцент-линией
- сильные **разделители** между секциями
- **альтернирующие background-тинты** (нечётные — синий слева, чётные — фиолетовый справа)
- min-height 90vh на каждой секции (ощущение «отдельная страница»)
- без 3D

**CINEMATIC** — текущий 3D-коридор без изменений.

### Форма заявок

Подключена к `APPS_SCRIPT_URL` константе в `index.html` (сейчас пустая — после деплоя Apps Script нужно вставить URL туда).

POSTит JSON `{name, phone, project, lang, mode, source}` на endpoint.
Поле `mode` показывает, из какого варианта сайта пришла заявка (landing/multipage/cinematic) — это полезно для аналитики.

Скрипт `apps-script.gs` готов: принимает POST, пишет строку в табу `leads` (создаёт автоматически с заголовками: Дата · Имя · Контакт · Проект · Язык · Формат · Источник), шлёт email на `johnaltmanandco@gmail.com`.

### Подключение фото коридоров

В коде уже прописаны пути `assets/corridors/corridor-01-entrance.jpg` ... `corridor-10-final-zone.jpg`.

JS на mobile проверяет, загружаются ли картинки:
- если **загрузились** → ставится класс `photos-loaded`, скрываются CSS-схематичные коридоры, показываются фото
- если **нет** → остаются CSS-схематичные коридоры как graceful fallback

Сцены 04 REELS и 11 LAUNCH **переиспользуют** другие фото:
- REELS = corridor-04-ai-video.jpg + **фиолетовый CSS overlay** поверх
- LAUNCH = corridor-01-entrance.jpg + **золотой CSS overlay** поверх

## Технические детали (если новый чат полезет в код)

### URL-параметры

- `https://сайт/` → chooser
- `https://сайт/?mode=landing` → landing-режим
- `https://сайт/?mode=multipage` → multipage-режим
- `https://сайт/?mode=cinematic` → cinematic-режим
- На мобиле всегда cinematic-mobile независимо от `?mode=`

### Ключевые места в коде

- **Раннее определение режима**: инлайн-скрипт в `<head>` (строки ~10–40), ставит классы на `<html>`
- **i18n**: const `i18n = { en, ru, uz }` (строка ~1640)
- **Apps Script URL**: const `APPS_SCRIPT_URL` (строка ~1700) — сюда вставить URL после деплоя
- **Three.js setup**: после `i18n` (строки ~1700–1900) — корридор, освещение, камера
- **SCENE_ACCENTS**: карта цветов по сценам (строки ~1530–1550)
- **Mobile root**: `<div id="mobile-root">` (строки ~1100–1620) — отдельный мобильный layer
- **Chooser HTML**: `<div id="chooser-root">` (строки ~1015–1090)
- **Mobile JS wiring**: IIFE в конце скрипта (строки ~2200–2350)

### Что НЕ трогать

- Структуру 17 секций `<section class="stage" data-stage="N">` — на ней завязан и десктоп, и мобила, и i18n, и счётчик сцен
- Существующие video-теги в начале body (даже если визуально не используются — Three.js может ссылаться)
- Систему языков (data-i18n атрибуты в каждом тексте)
