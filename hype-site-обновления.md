## ТЕКСТ: каждая сцена знает «где у неё дыра под текст»

Главный принцип: 3D-композиция и текст планируются вместе. Не «текст слева/справа всегда», а «у каждой сцены свой text-safe zone».

### Правила позиционирования по сценам

| Сцена | Где текст |
|---|---|
| LOBBY | Заголовок строго в **верхней половине**, порталы только в нижней дуге |
| COMMERCIAL | Биллборд занимает 60% справа. Текст в безопасной зоне 40% слева, выровнен по биллборду |
| AI Video | Текст сбоку с большим отступом от сферы. Или как «стикер на стекле» поверх нижней части сферы |
| Reels | Телефоны разбросаны, но угол **всегда свободен** под текст. Телефоны туда не залазят |
| Brand Films | Заголовок мелкий **под экраном**, как название фильма на афише. Не сверху, не сбоку |
| Motion + Product | Огромный заголовок «POLISH THAT SELLS» **горизонтально между половинами** зала |
| AI Sites | Заголовок сверху по центру, 3 портала снизу. Чёткая граница |
| Pricing | Заголовок над капсулами, названия пакетов **под каждой капсулой** (не сбоку) |
| Portfolio | Короткий заголовок слева сверху, **без описания снизу** (стена сама говорит) |
| Process | Заголовок над киноплёнкой |
| Contact | Форма справа, контакты слева, заголовок сверху по центру |

### Шапка и логотип
- H2 в сценах начинается с отступа сверху **≥80px** — чтобы шапка не пересекалась с заголовками
- Логотип в шапке всегда отдельным слоем, не лезет в 3D-контент

### Два стиля текста — выбирать для каждой сцены
1. **«Подпись к экспонату»** — мелкий текст в углу, с уважением к 3D
2. **«Часть сцены»** — огромный текст на фоне, как партовый кадр в фильме

Уходим от среднего «текст в центре, всё мешает всему».

## 1. LAPTOP-ПОРТАЛ (приоритет — высокий)

### Скрыть видео-сцены позади ноутбука
Сейчас LOBBY виден позади корпуса с самого начала — портит магию «прохода сквозь экран».

- `scene.background = black` во время laptop-стадии
- Поджать fog с (8, 60) до (4, 15) — всё дальше ~15 единиц растворяется
- На zoom-in (progress > 0.7) плавно вернуть fog к норме — lobby «проявляется»
- Опционально: чёрная плоскость-задник на z = +12 для гарантии

### Реалистичный корпус (в порядке важности)

1. **Цвет:** space-gray `#2a2a2c`, metalness 0.85, roughness 0.25-0.35 (сейчас слишком синий)
2. **Клавиатура:** ~78 InstancedMesh клавиш, чёрный мат, тонкая cyan-подсветка под клавишами
3. **Бэзел экрана:** 5-8мм чёрная рамка вокруг display-плоскости
4. **Стеклянный трекпад:** тёмное стекло с лёгким отражением
5. **Скос углов:** ExtrudeGeometry с rounding вместо BoxGeometry
6. **Логотип HYPE на крышке:** светящийся cyan «▍ HYPE»

### Освещение
- Тёплый bounce-light снизу `#d9c8a9`
- Hard highlight сверху на металле крышки
- Круглая мягкая тень под корпусом (сейчас «парит»)

### Build-фаза с дыханием

| % | Что происходит |
|---|---|
| 0-15% | Силуэт корпуса (внешние линии) |
| 15-25% | Внутренние линии: клавиатура, трекпад, бэзел |
| 25-40% | Solid металл материализуется, wireframe гаснет |
| 40-55% | Лид открывается |
| 55-70% | Экран загорается |
| 70-100% | Камера в экран, fog растворяется → lobby |

## 3. БИЛД-АНИМАЦИИ ДЛЯ КАЖДОЙ СЦЕНЫ (приоритет — критический)

Сейчас всё уже на месте когда камера приезжает. Только laptop имеет драматургию (каркас → материализация). Распространяем этот принцип на все сцены.

### Триггер
Анимация запускается **за 30% пути до сцены** (когда камера приближается). При уходе камеры — обратное отключение.

### Что происходит в каждой сцене

| Сцена | Билд-анимация |
|---|---|
| Commercial | Каркас биллборда падает с неба → материализуется → загорается видео → из-под земли вырастают силуэты небоскрёбов (как Matrix-город грузится) |
| AI Video | Точки вспыхивают в воздухе → соединяются линиями → собираются в сферу-нейросеть → в центре «бутится» видео |
| Reels | Телефоны прилетают из-за камеры с разных сторон → останавливаются → экраны включаются с щелчком |
| Brand Films | Темно → загораются боковые лайт-стрипы → последним большой экран (как сеанс начинается) |
| Motion + Product | Буквы HYPE собираются из частиц / Подиум поднимается из пола, спотлайты по очереди включаются (тип-тип-тип) |
| AI Sites | Порталы «бутятся»: чёрные рамки → строки кода как при загрузке системы → картинка проявляется |
| Pricing | Три капсулы вырастают из пола вверх → внутри загорается светящаяся колба |
| Portfolio | Экраны включаются как камеры наблюдения, по одному в шахматном порядке |
| Process | Киноплёнка протаскивается слева направо, кадры появляются последовательно |

### Эффект
**Заходишь в комнату → свет включается → объекты материализуются → ты внутри живой сцены.** Каждый раз новое впечатление, не статичная декорация.

## 5. МОБИЛЬНАЯ ВЕРСИЯ (приоритет — критический, параллельно)

**70-80% трафика будет с мобильных** (Instagram bio, reels, мессенджеры). Не «потом» — половина проекта.

### Принципиально: НЕ запускать Three.js на мобильном
- **Десктоп (>900px):** полный 3D-полёт
- **Мобайл (<900px):** вертикальный reels-формат, каждая сцена = full-viewport секция с видео-фоном

### Концепция мобильного UX
| Раздел | На мобильном |
|---|---|
| Hero (Laptop) | Статичное фото/клип ноутбука + текст + Enter |
| Услуги | Каждая = вертикальная секция, видео на фоне, заголовок сверху |
| AI Sites | Вертикальный стек 3 карточек с превью-видео |
| Portfolio | Сетка 2×3, тап → fullscreen |
| Pricing | Карточки одна под другой |
| Process | Горизонтальный свайп stories (1 шаг за свайп) |
| Contact | Форма + крупные кнопки Instagram / Tap to call |

### Must-have технически
1. `scroll-snap-type: y mandatory` — браузер сам снапит секции
2. `100dvh` вместо `100vh` — учитывает адресную строку Safari
3. Lazy-load видео через IntersectionObserver — играет только текущее + следующее
4. Две версии каждого видео: десктоп 15МБ + мобайл 3-5МБ через `<source media="(max-width:900px)">`
5. Connection-aware loading через `navigator.connection.effectiveType`
6. `prefers-reduced-motion: reduce` — отключаем видео-фоны
7. Первый тап = разрешение autoplay

### Что НЕ делать на мобиле
- ❌ Three.js / WebGL
- ❌ Прелоадить все видео
- ❌ `background-attachment: fixed`
- ❌ Hover-эффекты без tap-эквивалента

## 6. ВИЗУАЛЬНЫЕ АПГРЕЙДЫ (приоритет — средний)

### Убрать wireframe-рамки везде кроме laptop
Они оправданы только в laptop-портале. В остальных — чертёж вместо пространства. Заменить на:
- Полы с лёгким отражением (`THREE.Reflector`)
- Ambient свет окружения
- Объёмные пространства (см. раздел «разные фоны»)

### Postprocessing: Bloom
`EffectComposer + UnrealBloomPass` — свечение ярких точек. Главная разница между «Three.js демо» и «cinematic».

### HDRI окружение
Бесплатные на polyhaven.com. Металлические объекты получают реалистичные отражения. Особенно нужно для:
- Корпус ноутбука
- Pricing-капсулы
- Бэзел кино-экрана
- Подиум в Product Ads

### Звук
- Один ambient-pad на всю длину
- Стингеры на переходах: whoosh, click, shutter, keyboard
- Сайт начинает «звучать» — залетает в reels

## 7. УРОКИ ИЗ ПРОШЛОГО РАУНДА (всегда применять)

Codex починил видео — что важно держать в коде:

1. **Лимит браузерных декодеров** — `syncSceneVideos(activeIndex)` играет только текущую сцену + соседние
2. **Кеширование VideoTexture** — Map, один texture на видео, переиспользовать
3. **`texture.needsUpdate = true` в render loop** — обязательно для VideoTexture в r128
4. **`autoplay` атрибут на `<video>`** — даже с JS-вызовом помогает
5. **НЕ прятать через `top: -9999px`** — использовать `width: 1px; height: 1px; opacity: 0`
6. **`preload="metadata"` (не "auto")** — экономия трафика на старте
7. **`powerPreference: 'high-performance'`** в WebGLRenderer
